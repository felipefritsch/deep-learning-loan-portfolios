Asset Loans Default Risk — Process Overview

Oxford MCF dissertation · Sirignano-style deep-learning mortgage transition models Status (12 Jun 2026): M1–M9 + M10a complete · next: M10b rolling backtest

The project at a glance

Replicate and extend Sirignano, Sadhwani & Giesecke — Deep Learning for Mortgage Risk (JFEC 2021) on the complete public Fannie Mae Single-Family Loan Performance dataset: estimate the monthly conditional state-transition distribution P(statet+1 | statet, xt) of US mortgages with deep nets, benchmark against an empirical transition matrix and multinomial logit on a strictly out-of-sample rolling backtest (2015–2025), then show the differences matter economically by rolling the model forward to pool-level prepayment/delinquency counts and translating them into CPR / WAL / price errors.

current→ 30 DPD→ 60 DPD→ 90+ DPD→ foreclosure→ REO |  prepaid

Seven states; in this dataset foreclosure / REO / prepaid are terminal (Zero-Balance-code derived), so origins are the four live states and the transition matrix is 4×7, not 7×7.

Data pipeline — six stages, S1–S6 DONE

src/floan/pipeline/ · spec: specs/pipeline/ · stack: DuckDB + Polars + PyArrow + Parquet(zstd)

Converts the raw CSVs — one quarter at a time, never fully in RAM — into a compressed columnar lake, then derives the seven-state transition panel that everything downstream consumes. Idempotent, per-quarter, resumable; the one hard rule is never load a full quarter into memory.

raw/Performance_All/*.csv (~800 GB, immutable) │ S1 inventory + integrity audit s1_inventory.py manifest, field counts, release cut-off │ S2 streaming CSV → Parquet s2_to_parquet.py interim/perf/acq_quarter=YYYYQn/ (zstd) │ S3 clean + standardise s3_clean.py interim/clean/ dates, categoricals, sentinels │ S4 transition panel s4_panel.py processed/panel/ state, state_next, censored, │ period_ym, orig_ym, shard = hash(loan) % 256 │ S5 DuckDB views + sampling s5_sample.py processed/samples/ + lake.duckdb catalog │ S6 QA + reconciliation s6_qa.py row-count reconcile, null/target audits ▼ cleaned loan-month panel: 3.31 B rows / 57.6 M loans / 104 partitions
Technical detail
  • Why this stack: Parquet+zstd compresses 4–8×; DuckDB queries the lake out-of-core with predicate/projection pushdown (SET memory_limit); Polars scan_* streams transforms; PyArrow chunked reader handles 25 GB files block-by-block. pandas only on filtered in-RAM slices.
  • Target derivation (S4): statet from Current Loan Delinquency Status + Zero Balance Code; state_next = same loan, month t+1; censored rows flagged and excluded from every likelihood.
  • Leakage safety baked in: calendar keys period_ym / orig_ym for strict temporal masks; deterministic loan-keyed shard (fixed-seed hash → 256 buckets) for loan-disjoint sampling; output sorted (shard, loan, period) for row-group skipping.
  • Invariants (root + pipeline CLAUDE.md): single ROOT in config.py; every stage calls require_drive(); stages idempotent and per-quarter; tasks executed one at a time against the Accept criteria of 03_CLAUDE_CODE_TASKS.md.
  • QA refinements committed along the way: feature quantiles estimated on a 2 % sample; orig_ym > period_ym reported as a data-quality note, not a FAIL.

Macro data block — MD1–MD4 DONE

spec: specs/model/05_MACRO_DATA.md · code: fetch_macro.py, build_macro.py, macro_features.py · = task M2b

A June-2026 decision reversed the original "macro out of scope" call: a small fixed set of macro series enters as two thin time-keyed Parquet tables joined at export time — the 800 GB lakes are never reprocessed. This unlocks the true refi incentive (vs PMMS) and mark-to-market LTV, the paper's key default driver.

Technical detail — features & training discipline
  • Features: continuous (rates, incentive, UPBs log, age, remaining term, LTV/CLTV/DTI, FICOs, MI%) standardized with train-only scalers; macro block (pmms30, unrate, ltv_mtm, hpi_chg_12m, dgs10/slope) with per-variable publication lags; categoricals (origin state, channel, purpose, property type/state, MSA, zip3, …) as embeddings with reserved UNK; month-of-year seasonality; no raw calendar time as a feature (test years are unseen values).
  • One multinomial model conditioned on origin state (paper's design), not four separate models; impossible transitions left for the model to learn ≈0 and QA-asserted < 0.1 % mass.
  • Imbalance handling: current→current rows kept with p_keep = 0.05 and loss importance-weighted (w = 1/p_keep) so probabilities stay unbiased; verified against unsampled base rates.
  • Reproducibility: every fit writes a self-describing run folder (config, git commit, manifest hash, window id, scaler, metrics.json); resumable checkpoints (bit-for-bit resume verified on GPU).
  • Per-window locality: scalers, vocabularies and the incentive index re-derived from each window's train slice — no leakage across windows.

Phase 3 — Pool-level analysis (M13–M15) PENDING

src/floan/model/pool.py (to be written) · spec: 03_POOL_LEVEL.md · consumes frozen Phase-2 models only

The economic punchline: roll each window's frozen model forward 12 months by composing monthly transition matrices (deterministic, no Monte Carlo; terminal states absorbing; first-passage trick for "ever 60+ DPD"), aggregate to pools, and compare predicted vs realized counts — then translate counts into CPR, WAL and price errors via a level-pay pass-through cashflow engine. The CPR/WAL/price translation plus the by-anchor regime exhibit are the dissertation's main beyond-replication contributions.

Technical detail
  • M13 — roll-forward harness: p ← p · Ph for h = 1…12; static features frozen at t0, age/term/seasonality evolve, macro frozen at t0 (stated assumption); unit-tested against a closed-form toy chain; h=1 must equal evaluate.py exactly.
  • M14 — pools: characteristic buckets (FICO × rate × LTV, ≥2,000 loans/pool) + 500 random pools of 1,000 loans; anchors at Dec(k−1) — all 11 if scoring allows, minimum the ensemble-bearing 2019-12 / 2022-12 / 2024-12; predicted count = Σ pi, Poisson-binomial intervals; R²/RMSE scatter vs realized per model.
  • M15 — economic translation (Phase-3 gate): UPB-weighted SMM/CPR paths → cashflow engine (unit-tested vs zero-prepay annuity and constant-SMM closed forms, ~1e-8) → CPR (pp), WAL (months), price (per 100) errors per pool × model × anchor → T5.1 + F5.2; headline = ensemble-vs-logit reduction in mean |price error|. Portfolio-decile sort deliberately deferred (pricing tests levels; sorts only ranking).
  • Memo 03_pool.md closes with the contributions paragraph: prime conforming credit box, 2015–2025 regimes incl. COVID + 2022-23 rate shock, the rolling-window protocol, and the CPR/WAL/price translation.

Cross-cutting: infrastructure, backup & working method STANDING

scripts/backup_ssd.sh · CLAUDE.md invariants · PROMPTS.md task protocol

Three machines, one discipline: the Mac runs everything that touches the panel lake (pipeline, EDA, exports, evaluation); a rented GPU pod runs training on rsynced compact exports (2.7 GB, not 800 GB); the SSD holds data + models. Work proceeds one milestone at a time via scripted prompts, each verified against explicit Accept criteria and committed before the next begins.

Technical detail
  • Backup tiers: code/specs/memos → git + GitHub; small irreplaceables (models, scalers, metrics, figures, manifests, macro tables) → backup_ssd.sh → ssd_mirror/ after every milestone gate and GPU session; Parquet lakes and raw/ → not backed up, rebuildable/re-downloadable (Stage-1 manifest provides checksums to verify a re-download).
  • GPU sessions: checkpoints synced back to models/ before pod teardown — never the only copy on a rented box; every GPU task keeps a --smoke CPU path (≤100 k rows).
  • Method: Karpathy-style guidelines (state assumptions, simplest thing, surgical diffs, verify Accept criteria with pasted evidence); one task per session/branch; results contradicting the paper are recorded, not tuned away.

The evaluation backbone: 11 rolling windows DESIGN

One window per test year k = 2015…2025 (2025 partial to the release cutoff). Train on labels ≤ Dec(k−2) (expanding from 2000), validate on year k−1 (early stopping only), test on year k. Splits stated on label months; masks enforce period_ym < cutoff. Hyperparameters tuned once on k=2015 and frozen; pooled all-years NLL = every 2015–2025 test row predicted exactly once by a model that never saw it. Regime shifts (COVID 2020-21, the 2022-23 rate spike) become test-year effects, not a cutoff choice.

train (expanding) validation (k−1) test (year k) ★ = ensemble-of-8 window (2015 · 2019 · 2020 · 2023 · 2025)

The model ladder (all share loss, data, eval path)

  • A — Empirical 4×7 matrix: row-normalized counts, Laplace α=0.5; no covariates — the floor. (+ optional bucketed variant.)
  • B — Multinomial logit: 0-hidden-layer net in PyTorch, one-hot categoricals, L2 on val; sklearn cross-checked. (+ optional augmented logit.)
  • C — Deep nets: MLP on [standardized continuous ‖ embeddings]; depth {1,3,5,7}, paper widths (200, 140×4), ReLU, dropout/L2 grid, Adam + AMP, early stopping on val NLL.
  • D — Ensemble: 8 independent nets, averaged probabilities, on the 5 key windows; NLL-vs-size curve (paper Fig 7).
  • Metrics: out-of-sample mean NLL (per year + pooled + by origin state), one-vs-rest AUC per transition, reliability diagrams, predicted-vs-realized rate overlay.

Known deviations from Sirignano et al. (stated in the writeup)

  • Dataset: public GSE prime conforming book vs CoreLogic private-label — lower base rates; nonlinearity strength is the open question.
  • States: foreclosure/REO/prepaid terminal here → 4×7 matrix, not 7×7; all models share the origin set, so comparisons stay apples-to-apples.
  • Macro granularity: national rates, state unemployment/HPI (vs zip/county) — channels present, local variation a stated limitation + future-work hook.
  • Period: 2000–2025 (vs 1995–2014) — test regimes include COVID forbearance and the 2022-23 rate shock.
