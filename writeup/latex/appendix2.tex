\chapter{Reproducibility}
\label{app:reproducibility}

This appendix records the computing environment and the data-snapshot
and run-record conventions referenced in
Section~\ref{sec:meth-repro}. The guiding principle is that every
number reported in Chapters~\ref{chap:loanlevel}
and~\ref{chap:poollevel} can be traced from the
exhibit back to the exact code revision and data slice that produced
it.

\section{Pipeline summary}
\label{sec:repro-pipeline}

The estimation panel is built from the Fannie Mae Single-Family Loan
Performance dataset --- roughly one hundred quarterly vintage files
spanning 2000--2025, about 800\,GB of raw CSV. The pipeline never loads
a full quarter into memory: every stage streams through DuckDB, Polars,
and PyArrow, transforming the immutable \texttt{raw/} tree into
\texttt{interim/} and then \texttt{processed/} artifacts on the external
data drive, and each stage is idempotent and runs per quarter so a
build can be resumed exactly where it stopped. The result is a monthly
seven-state panel of 3.31 billion loan-months across 57.6 million
loans. For estimation, the dominant \emph{current}$\to$\emph{current}
transition is class-thinned at a keep rate of $0.05$ and the surviving
rows carry Horvitz--Thompson inverse-probability weights, so the thinned
loss remains an unbiased estimate of the full-sample loss; loans are
hashed into 256 shards to support the loan-keyed two-level shuffle of
Section~\ref{sec:meth-shards}.

\section{Run records and manifest conventions}
\label{sec:repro-records}

The training export writes a \texttt{manifest.json} recording the
design variant, the Git commit, the construction parameters, and the
per-pool row counts together with a content hash of the train and eval
pools. Table~\ref{tab:repro-manifest} summarises the full-design
export. Every subsequent model fit --- empirical, logit, network, and
ensemble --- writes its own \texttt{metrics.json} run record carrying
the Git commit, the random seed, the window identity, the architecture,
the out-of-sample metrics, and the content hashes of the train and eval
pools it consumed. Because the run record stores the pool content
hashes alongside the code commit, any reported figure resolves to a
single \{commit, data-slice, window, seed\} tuple, and a re-run on the
same manifest reproduces it.

\section{Computing environment}
\label{sec:repro-env}

Work was split across two kinds of machine. The full-scale neural
networks were fit on a rented GPU node --- an NVIDIA RTX~A4500 (20\,GB),
PyTorch \texttt{2.8.0+cu128} on CUDA~12.8 and cuDNN~9.10, with automatic
mixed precision --- as recorded in the \texttt{environment} block of
each network run record; an earlier dev-scale fit used an RTX~4090. The
data pipeline, the exploratory analysis, the logit and empirical
baselines, and the entire pool-level Phase~3 (roll-forward, cashflow
engine, and economic translation) ran on the project's local Mac on
CPU. Network weights use the PyTorch defaults: linear layers are
initialised by Kaiming-uniform sampling ($a=\sqrt{5}$, biases uniform on
$\pm 1/\sqrt{\text{fan-in}}$) and categorical embeddings from the
standard normal $\mathcal{N}(0,1)$; no custom initialiser is applied.
